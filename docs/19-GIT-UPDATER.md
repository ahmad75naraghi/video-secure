# ۱۹ — آپدیت امن از گیت‌هاب

این سند بخش «آپدیت از گیت» را توضیح می‌دهد: چه چیزی ذخیره می‌شود، آپدیت چطور انجام می‌شود، چه چیزهایی محافظت می‌شوند و اگر چیزی خراب شد چطور بازگردانی کنیم.

> **خلاصه در یک خط:** فایل ZIP مخزن دانلود می‌شود، پیش از هر تغییری از نصب فعلی پشتیبان گرفته می‌شود، syntax همهٔ فایل‌های PHP بررسی می‌شود و سپس فایل‌ها با فایل‌های واقعی افزونه هم‌گام می‌شوند — بدون `exec`، بدون `git`، بدون `unzip` و بدون تغییر نام یا جابه‌جایی پوشهٔ افزونه.

## ۱. مسیر دسترسی در پنل

```text
ویدیوهای امن  →  آپدیت از گیت
```

زیرمنوی «آپدیت از گیت» زیر منوی اصلی افزونه (`edit.php?post_type=falnic_video`) قرار دارد و برای دیدن/استفاده از آن باید دسترسی **`update_plugins`** داشته باشید (معمولاً فقط مدیر کل).

تب‌های بالای صفحه‌ها، همهٔ بخش‌های مدیریت افزونه را به هم وصل می‌کنند:

| تب | صفحه | دسترسی |
| --- | --- | --- |
| تنظیمات امنیتی | `falnic_hls_settings` | `manage_options` |
| تنظیمات قالب | `falnic_template_settings` | `manage_options` |
| انکودر دستی | `falnic_hls_encoder` | `manage_options` |
| آپدیت از گیت | `falnic-git-update` | `update_plugins` |

## ۲. تنظیمات منبع

| فیلد | آپشن | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| مخزن | `falnic_git_repo` | خالی | فقط قالب `owner/repo`. هر چیز دیگری رد می‌شود. |
| شاخه | `falnic_git_branch` | `main` | فقط `A-Z a-z 0-9 . _ - /` با قاعده‌های ایمن (بدون `..`، بدون `//`، بدون اسلش ابتدا/انتها). |
| توکن | `falnic_git_token` | خالی | اختیاری؛ فقط برای مخزن خصوصی یا عبور از سقف درخواست. |

**رفتار توکن (سخت‌گیرانه):**

- فیلد ورودی از نوع `password` است و **همیشه خالی** رندر می‌شود؛ مقدار ذخیره‌شده هرگز در HTML، پاسخ AJAX، لاگ یا جاوااسکریپت نوشته نمی‌شود.
- وضعیت فقط به‌صورت «توکن ذخیره شده» یا «توکن ذخیره نشده» نشان داده می‌شود.
- اگر فیلد را خالی بگذارید و ذخیره کنید، توکن قبلی **دست‌نخورده** می‌ماند.
- فقط با تیک‌زدن «حذف توکن ذخیره‌شده» مقدار پاک می‌شود.

## ۳. پیش‌نیازهای سرور

پیش از هر عملیات، این موارد بررسی می‌شوند و اگر یکی نبود، دکمه‌های آپدیت غیرفعال می‌شوند:

| پیش‌نیاز | چرا |
| --- | --- |
| کلاس `ZipArchive` | باز کردن و اعتبارسنجی ZIP بدون فرمان `unzip` |
| تابع `token_get_all` با `TOKEN_PARSE` | بررسی syntax بدون اجرای کد |
| قابل‌نوشتن بودن پوشهٔ وردپرس (نصب افزونه) | هم‌گام‌سازی فایل‌ها |
| قابل‌نوشتن بودن `uploads/` | ساخت پشتیبان |

## ۴. جریان آپدیت (گام‌به‌گام)

1. **بررسی نسخه** — سه درخواست به API گیت‌هاب:
   - `GET /repos/{owner}/{repo}` → وجود مخزن و خصوصی بودن
   - `GET /repos/{owner}/{repo}/commits/{branch}` → آخرین SHA
   - `GET /repos/{owner}/{repo}/zipball/{branch}` → خودِ بستهٔ کد

   هر درخواست با `timeout: 20`، `sslverify: true` و `User-Agent: Falnic-Secure-HLS-Updater/{version}` ارسال می‌شود. توکن فقط در هدر `Authorization: Bearer …` قرار می‌گیرد.

2. **پیام‌های خطای متمایز** (هر مورد پیام فارسی مستقل دارد):

   | وضعیت | کد خطا | پیام |
   | --- | --- | --- |
   | قالب مخزن نامعتبر | `falnic_repo_missing` | ابتدا مخزن گیت‌هاب را در کارت تنظیمات ذخیره کنید. |
   | 404 | `falnic_not_found` | مخزن پیدا نشد… |
   | 401 | `falnic_bad_token` | توکن گیت‌هاب معتبر نیست یا منقضی شده است. |
   | 403 | `falnic_no_access` | دسترسی به این مخزن وجود ندارد… |
   | 403 + `x-ratelimit-remaining: 0` یا 429 | `falnic_rate_limited` | سقف درخواست‌های گیت‌هاب پر شده است… |
   | 404 روی commits | `falnic_branch_missing` | برنچ موردنظر در مخزن پیدا نشد. |
   | 5xx و بقیه | `falnic_http` | گیت‌هاب پاسخ ناموفق برگرداند (کد N). |
   | خطای شبکه/cURL | `falnic_network` | اتصال به گیت‌هاب برقرار نشد (خطای شبکه یا cURL). |
   | Timeout | `falnic_timeout` | اتصال … با تایم‌اوت مواجه شد… |
   | خطای گواهی | `falnic_ssl` | خطای گواهی SSL… |
   | پاسخ ۲۰۰ نامعتبر/HTML | `falnic_unexpected` | پاسخ گیت‌هاب غیرمنتظره بود. |

3. **اعتبارسنجی ZIP** (`validate_zip`) — بدون استخراج:
   - فایل واقعاً ZIP است (خطای `ZipArchive::open` گرفته می‌شود؛ صفحهٔ HTML یا صفحهٔ ورود به‌عنوان ZIP پذیرفته نمی‌شود).
   - هیچ entry با `..`، مسیر مطلق، درایو ویندوزی (`C:\`)، کاراکتر NUL یا symlink وجود ندارد.
   - ساختار یا **یک پوشهٔ ریشه** دارد (zipball گیت‌هاب) یا **بدون ریشه** است (پشتیبان داخلی)؛ بیش از یک ریشه یا ریشهٔ تودرتو رد می‌شود.
   - فایل اصلی افزونه (`falnic-secure-hls.php`) داخل بسته هست و هدر `Plugin Name:` دارد.

4. **قفل هم‌زمانی** — transient `falnic_git_lock` با TTL ۹۰۰ ثانیه. اگر عملیات دیگری در جریان باشد، پیام «یک عملیات به‌روزرسانی یا بازگردانی در حال اجراست» برگردانده می‌شود.

5. **پشتیبان‌گیری** — ZIP از کل پوشهٔ افزونه در `wp-content/uploads/falnic-backups/` ساخته می‌شود (بیرون از خود افزونه، تا با هم‌گام‌سازی حذف نشود). نام فایل:

   ```text
   falnic-before-update-20261020-153012-a1b2c3.zip
   ```

   - `.git` و فایل‌های موقت مستثنا هستند.
   - نگهداشت پیش‌فرض **۵** پشتیبان آخر است (فیلتر `falnic_git_max_backups`، محدود به ۱ تا ۲۰).
   - پوشهٔ پشتیبان با `.htaccess` (deny) و `index.php` محافظت می‌شود.

6. **Preflight** — بسته در پوشهٔ موقت زیر `falnic-backups/tmp/` باز می‌شود و **همهٔ** فایل‌های PHP با `token_get_all( $src, TOKEN_PARSE )` بررسی می‌شوند. در صورت خطا، حداکثر چند خطای اول گزارش و **هیچ تغییری روی نصب اعمال نمی‌شود**.

7. **اعمال تغییرات** (`apply`) — فقط در همین مرحله فایل‌های نصب لمس می‌شوند:
   - فایل‌های جدید کپی می‌شوند.
   - فایل‌های تغییرکرده بازنویسی می‌شوند.
   - فایل‌هایی که در نسخهٔ جدید نیستند حذف می‌شوند.
   - پوشه‌های خالی هرس می‌شوند.
   - **هرگز** حذف نمی‌شوند: فایل اصلی فعال افزونه، `.git`، پوشهٔ ریشهٔ افزونه.

8. **گزارش** — شاخه، SHA (۷ کاراکتری)، نسخهٔ قبلی → نسخهٔ جدید، مسیر پشتیبان، تعداد و فهرست فایل‌های افزوده/تغییرکرده/حذف‌شده، و هشدارهای پس از اعمال (مثلاً نبود فایل اصلی).

## ۵. بازگردانی (Rollback)

- فقط فایل‌هایی که **داخل** `falnic-backups/` هستند و نامشان با الگوی `falnic-[a-z0-9-]+.zip` می‌خواند پذیرفته می‌شوند.
- پیش از بازگردانی، از وضعیت فعلی هم پشتیبان گرفته می‌شود (`falnic-before-rollback-…`).
- خودِ فایل پشتیبان با همان اعتبارسنجی ZIP بررسی می‌شود.
- فایل‌های اضافه حذف، فایل اصلی حفظ و ریشهٔ پوشه دست‌نخورده می‌ماند.
- حذف پشتیبان دستی است (دکمهٔ «حذف» + تأیید مرورگر) و فقط روی همان پوشهٔ پشتیبان اثر دارد.

## ۶. امنیت

| موضوع | پیاده‌سازی |
| --- | --- |
| دسترسی | `current_user_can( 'update_plugins' )` در فرم تنظیمات، هر چهار هندلر AJAX و در رندر صفحه |
| nonce | `falnic_git_settings` برای فرم (`check_admin_referer`) و `falnic_git_ajax` برای AJAX (`check_ajax_referer`) |
| پاسخ‌ها | فقط `wp_send_json_success` / `wp_send_json_error` |
| ورودی‌ها | `sanitize_text_field`، `sanitize_file_name`، `sanitize_key` + اعتبارسنجی اختصاصی |
| مسیرها | مسیر افزونه از محل فایل خود افزونه (نه از نام مخزن)؛ نام پشتیبان با `basename` و regex بررسی می‌شود |
| فرمان‌ها | هیچ `exec/shell_exec/system/passthru/proc_open/popen` و هیچ فراخوانی `git`/`unzip` |
| توکن | فقط در هدر درخواست؛ نه در خروجی، نه در گزارش، نه در JS |
| خروجی HTML | همهٔ مقادیر با `esc_html`/`esc_attr`/`esc_url` |

## ۷. ساختار فایل‌ها (تفکیک منطق از UI)

```text
includes/class-git-updater.php     ← منطق کامل: تنظیمات، HTTP، ZIP، lint، پشتیبان، apply، rollback، قفل
admin/class-git-update-page.php    ← UI controller: منو، enqueue، هندلرهای admin-post و AJAX، رندر
admin/views/git-update.php         ← مارک‌آپ سه کارت (تنظیمات / آپدیت / پشتیبان‌ها)
assets/js/admin-git.js             ← کلاینت AJAX (fetch + textContent، بدون innerHTML)
assets/css/admin.css               ← استایل محدود به .falnic-admin
```

`includes/class-git-updater.php` از فایل اصلی افزونه بارگذاری می‌شود، پس هندلرها روی **همهٔ** درخواست‌های مدیریت ثبت می‌شوند (نه فقط صفحهٔ آپدیت).

## ۸. تست‌ها

```bash
# ۱) تست‌های واحد منطق (نیازمند PHP CLI)
php tests/run-tests.php

# ۲) بررسی syntax همهٔ فایل‌های PHP (بدون اجرا)
php tests/lint-all.php

# ۳) بررسی‌های امنیتی ایستا (بدون وابستگی)
node tests/static-checks.js
```

پوشش تست‌ها: اعتبارسنجی repo/branch/نام پشتیبان، مسیرهای ناامن ZIP، symlink، تشخیص فایل اصلی، نگهداشت پشتیبان، lint بدون اجرا، هم‌گام‌سازی فایل‌ها (added/changed/removed + حفظ `.git` و فایل اصلی)، رد شدن rollback نامعتبر، قفل هم‌زمانی، افشا نشدن توکن، و پیام‌های خطای متمایز API (۴۰۱/۴۰۳/۴۰۴/۴۲۹/۵۰۰/تایم‌اوت/پاسخ نامعتبر/شاخهٔ ناموجود).

## ۹. عیب‌یابی

| نشانه | علت احتمالی | کار |
| --- | --- | --- |
| «ZipArchive روی سرور فعال نیست» | افزونهٔ `zip` در PHP نصب نیست | از هاست بخواهید `php-zip` را فعال کند |
| «هدر افزونه … خوانده نشد» | ساختار مخزن متفاوت است | مطمئن شوید `falnic-secure-hls.php` در ریشهٔ مخزن است |
| «فایل اصلی نسخهٔ جدید با فایل فعال این نصب یکسان نیست» | نام فایل اصلی عوض شده | نام فایل اصلی افزونه را برنگردانید؛ افزونه با همین نام فعال است |
| «سقف درخواست‌های گیت‌هاب پر شده است» | سقف ۶۰ درخواست/ساعت برای IP | توکن اضافه کنید |
| «یک عملیات … در حال اجراست» | قفل ۱۵ دقیقه‌ای پس از یک خطای ناگهانی | چند دقیقه صبر کنید یا transient `falnic_git_lock` را حذف کنید |

## ۱۰. محدودیت‌ها

- فقط از **گیت‌هاب عمومی/خصوصی با توکن** پشتیبانی می‌شود؛ GitLab/Bitbucket پشتیبانی نمی‌شوند.
- آپدیت، **کد** را هم‌گام می‌کند؛ داده‌های داخل `uploads/falnic-backups` و ویدیوهای رمزنگاری‌شده دست نمی‌خورند.
- وابستگی‌ها (`assets/vendor/…`) بخشی از مخزن‌اند؛ اگر در مخزن نباشند، در آپدیت حذف می‌شوند.
- بازگردانی، فایل‌ها را برمی‌گرداند ولی مهاجرت‌های دیتابیس را برنمی‌گرداند.
- این بخش جایگزین بکاپ کامل هاست نیست؛ برای بازگردانی کل سایت از بکاپ سرور استفاده کنید.
