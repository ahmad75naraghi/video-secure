# ۰۴ — نیازها و معیار پذیرش

این سند چهار خواسته‌ی شما را به نیازهای قابل تست تبدیل می‌کند. هر نیاز شناسه دارد و در [۱۴-تست](14-TESTING.md) به سناریو وصل می‌شود.

## خلاصه

| شناسه | نیاز شما | اولویت | وضعیت فعلی |
|---|---|---|---|
| R1 | ویدیو قابل دانلود نباشد | باید (Must) | ❌ شکست |
| R2 | واترمارک نام کاربری و ایمیل | باید (Must) | ⚠️ ناقص |
| R3 | جلوگیری از ضبط صفحه و سرقت | باید تا حد امکان | ⚠️ ناقص |
| R4 | قرار گرفتن در درس یک دوره | باید (Must) | ❌ ندارد |

## R1 — مقاومت در برابر دانلود

### صورت مسئله
کاربر نتواند با ابزار ساده (کلیک راست، افزونه‌ی دانلود، `wget`، `yt-dlp`) فایل ویدیو را به دست آورد.

### نیازهای عملکردی
| کد | نیاز |
|---|---|
| R1.1 | هیچ URL ثابت و عمومی به فایل `.m3u8`/`.ts` وجود نداشته باشد |
| R1.2 | همه‌ی درخواست‌های manifest/segment/key از یک کنترلر با احراز هویت عبور کنند |
| R1.3 | هر URL استریم به یک توکن کوتاه‌عمر (پیش‌فرض ۱۰ دقیقه) و به شناسه‌ی نشست گره بخورد |
| R1.4 | توکن قابل تمدید باشد (بدون بارگذاری دوباره‌ی صفحه) و در صورت بستن نشست باطل شود |
| R1.5 | دکمه/منوی «دانلود» در پلیر وجود نداشته باشد و `controlsList="nodownload"` ست شود |
| R1.6 | کلید رمزنگاری فقط برای کاربر مجاز و متناسب با بازه‌ی زمانی همان `key_id` تحویل شود |
| R1.7 | محدودیت نرخ روی درخواست‌ها اعمال شود (پیش‌فرض: ۶۰ درخواست سگمنت در دقیقه برای هر نشست) |
| R1.8 | در صورت وجود CDN، امضای URL با CDN هم‌سازگار باشد ([۰۹](09-STREAM-DELIVERY.md#cdn)) |

### معیار پذیرش
| # | داده‌ی ورودی | عمل | نتیجه‌ی مورد انتظار |
|---|---|---|---|
| A1.1 | کاربر مهمان | `GET /falnic/v1/manifest/v_xxx` | `401` |
| A1.2 | کاربر لاگین‌کرده‌ی غیرمجاز | همان درخواست | `403` + رکورد در لاگ |
| A1.3 | کاربر مجاز | همان درخواست با توکن معتبر | `200` + m3u8 با URLهای امضاشده |
| A1.4 | توکن منقضی | درخواست سگمنت | `403` (مهمان: `401`) + پیام `falnic_token_expired` |
| A1.5 | هر کسی | `GET /wp-content/uploads/secure_videos/...` | `403` یا `404` (فایل وجود ندارد) |
| A1.6 | کاربر مجاز | تلاش برای گرفتن سگمنت با توکن کاربر دیگر | `403` |
| A1.7 | ابزار `yt-dlp` | `yt-dlp <page-url>` | شکست: «No video formats found» |

> **آگاهانه:** A1.7 برای یک کاربر مجاز و متخصص در نهایت قابل دور زدن است (او می‌تواند کوکی و توکن خودش را بگذارد). هدف، بالا بردن هزینه و **قابل ردیابی کردن** است، نه تضمین مطلق. [۰۳-مدل تهدید](03-THREAT-MODEL.md#t-1--دانلود-مستقیم-فایلهای-استریم)

## R2 — واترمارک نام کاربری و ایمیل

### صورت مسئله
روی ویدیو، هویت بیننده دیده شود تا اگر تصویر منتشر شد، بدانید از کدام حساب بیرون آمده.

### نیازهای عملکردی
| کد | نیاز |
|---|---|
| R2.1 | واترمارک حداقل شامل **نام نمایشی یا نام کاربری** باشد |
| R2.2 | ایمیل نمایش داده شود، اما به‌صورت پیش‌فرض **ماسک‌شده** (`ah***@example.com`)؛ حالت کامل قابل تنظیم |
| R2.3 | علاوه بر این‌ها، یک **شناسه‌ی کوتاه نشست** (مثل `S-7F3A2C`) و **زمان** در واترمارک باشد تا نشتی قابل تاریخ‌گذاری باشد |
| R2.4 | واترمارک در حالت پخش، توقف، جست‌وجو و تغییر کیفیت دیده شود |
| R2.5 | موقعیت واترمارک در طول پخش جابه‌جا شود و در چند نقطه تکرار شود (حذف آن سخت شود) |
| R2.6 | واترمارک در فول‌اسکرین موبایل هم دیده شود (فول‌اسکرین روی کانتینر، نه `video` بومی) |
| R2.7 | برای دوره‌های حساس، گزینه‌ی **واترمارک سرورساید** (سوخته در تصویر) وجود داشته باشد |
| R2.8 | واترمارک از یک منبع سمت سرور و امضاشده بیاید، نه از متغیر JS قابل تغییر |

### معیار پذیرش
| # | عمل | نتیجه‌ی مورد انتظار |
|---|---|---|
| A2.1 | پخش با کاربر «علی رضایی» / `ali@example.com` | واترمارک شامل نام، ایمیل و شناسه‌ی نشست |
| A2.2 | تغییر `first_name` در پروفایل توسط خود کاربر | واترمارک در بارگذاری بعدی به‌روز شود، بدون XSS |
| A2.3 | توقف + seek به وسط ویدیو | واترمارک بلافاصله بازسازی شود |
| A2.4 | ورود به فول‌اسکرین روی iOS | واترمارک دیده شود |
| A2.5 | حذف `canvas` با DevTools | پخش قطع شود و رخداد لاگ شود (بهترین تلاش) |
| A2.6 | فعال بودن واترمارک سرورساید | واترمارک در فایل خروجی `ffmpeg` هم موجود باشد |

## R3 — کاهش ضبط صفحه و سرقت

### صورت مسئله
تا جای ممکن از ضبط و بازنشر جلوگیری شود. (توجه: «جلوگیری مطلق» ممکن نیست — [۰۳](03-THREAT-MODEL.md))

### نیازهای عملکردی
| کد | نیاز |
|---|---|
| R3.1 | هر پخش/کلید/رد درخواست در جدول لاگ ثبت شود (کاربر، ویدیو، IP، UA، زمان، نتیجه) |
| R3.2 | محدودیت پخش هم‌زمان بر اساس heartbeat (پیش‌فرض ۲ نشست) |
| R3.3 | تشخیص عدم فعالیت: اگر heartbeat قطع شود، نشست پس از ۹۰ ثانیه باطل شود |
| R3.4 | پنهان‌سازی سطحی نشانه‌های فنی: بدون `eval`، بدون `debugger`، بدون بستن صفحه |
| R3.5 | غیرفعال کردن PiP، منوی زمینه، و کلیدهای ذخیره (به‌عنوان بازدارنده‌ی سبک) |
| R3.6 | مسدود کردن درخواست‌های بدون Referer/Origin معتبر برای توکن |
| R3.7 | امکان افزودن هدر `Clear-Site-Data` هنگام خروج از حساب (اختیاری) |
| R3.8 | گزارش نشتی: امکان جست‌وجو در لاگ بر اساس شناسه‌ی نشستِ دیده‌شده در ویدیوی لو رفته |

### معیار پذیرش
| # | عمل | نتیجه |
|---|---|---|
| A3.1 | سه دستگاه هم‌زمان با یک حساب | سومین نشست رد شود + پیام روشن |
| A3.2 | بستن ناگهانی مرورگر | نشست پس از ۹۰ ثانیه غیرفعال شود |
| A3.3 | درخواست سگمنت با `Origin: https://evil.example` | `403` |
| A3.4 | جست‌وجوی `S-7F3A2C` در پنل لاگ | نمایش کاربر، ویدیو، زمان و IP همان نشست |
| A3.5 | بررسی کد | هیچ `eval`، هیچ `debugger`، هیچ `document.body.innerHTML` در پلاگین نباشد |

## R4 — قرار گرفتن در درس دوره (LearnDash)

### صورت مسئله
ویدیو بخشی از یک درس باشد و فقط دانشجوی همان دوره ببیند؛ بدون کپی‌کردن iframe و بدون کد دستی.

### نیازهای عملکردی
| کد | نیاز |
|---|---|
| R4.1 | متاباکس «ویدیوی امن» در صفحه‌ی ویرایش درس (`sfwd-lessons`) و مبحث (`sfwd-topic`) |
| R4.2 | انتخاب ویدیو از فهرست ویدیوهای پلاگین با جست‌وجو (بدون تایپ نام) |
| R4.3 | نمایش خودکار پلیر بالای/پایین محتوای درس بر اساس تنظیم، بدون نیاز به شورت‌کد |
| R4.4 | شورت‌کد `[falnic_lesson_video]` برای ویدیوی درس جاری |
| R4.5 | شورت‌کد `[secure_video id="123"]` برای استفاده‌ی دستی |
| R4.6 | بررسی دسترسی با `sfwd_lms_has_access( $course_id, $user_id )` در رندر، manifest، سگمنت و کلید |
| R4.7 | پشتیبانی از Course Builder و درس‌های مشترک (`learndash_get_course_id`) |
| R4.8 | احترام به قوانین خود LearnDash: درس نمونه، Drip/زمان‌بندی، گروه، پیش‌نیاز |
| R4.9 | بدون LearnDash، پلاگین باید با نقش/قابلیت `falnic_watch_videos` کار کند و خطا ندهد |
| R4.10 | سازگاری با pagination و قالب‌های LearnDash (بدون شکستن چیدمان) |

### معیار پذیرش
| # | عمل | نتیجه |
|---|---|---|
| A4.1 | دانشجوی ثبت‌نام‌کرده درس ۱۰ | ویدیو پخش می‌شود |
| A4.2 | کاربر لاگین بدون ثبت‌نام | پیام «برای دیدن این ویدیو باید در دوره ثبت‌نام کنید» + `403` در شبکه |
| A4.3 | مهمان | هدایت به صفحه‌ی ورود با `redirect_to` |
| A4.4 | کپی URL درس در مرورگر دیگر (کاربر دیگر) | `403` |
| A4.5 | درس با Drip هنوز باز نشده | ویدیو نمایش داده نشود و پیام زمان باز شدن |
| A4.6 | غیرفعال کردن LearnDash | شورت‌کد با نقش‌های مجاز کار کند، بدون `Fatal error` |
| A4.7 | درس با Course Builder | ویدیو درست به درس متصل شود |

## نیازهای غیرعملکردی

| کد | نیاز | معیار |
|---|---|---|
| NFR-1 | کارایی | شروع پخش < ۲ ثانیه در شرایط عادی؛ سربار PHP روی سگمنت < ۳۰ms |
| NFR-2 | مقیاس | پشتیبانی از ۲۰۰ پخش هم‌زمان روی یک VPS معمولی (با X-Accel/Nginx) |
| NFR-3 | سازگاری | Chrome/Edge/Firefox/Safari آخرین دو نسخه + iOS 15+ + Android Chrome |
| NFR-4 | دسترس‌پذیری | کنترل با کیبورد، زیرنویس، `aria-label`، احترام به `prefers-reduced-motion` |
| NFR-5 | حریم خصوصی | ماسک ایمیل به‌صورت پیش‌فرض؛ سیاست نگهداری لاگ ۹۰ روزه |
| NFR-6 | نگهداری | PHP 7.4+، WPCS، i18n، بدون `eval`، بدون وابستگی CDN اجباری |
| NFR-7 | پشتیبان‌گیری | سازگار با بکاپ‌گیری فایل و DB؛ کلیدها همراه فایل‌ها |
| NFR-8 | چندزبانه | همه‌ی رشته‌ها با `__()` و text domain |

## خارج از دامنه (Non-goals)

- DRM سخت‌افزاری (Widevine/FairPlay) — تصمیم در [ADR-004](17-ADR.md#adr-004)
- فروشگاه/درگاه پرداخت
- پخش زنده (Live)
- تبدیل خودکار زیرنویس با هوش مصنوعی
- مدیریت دوره‌ها (به LearnDash واگذار می‌شود)

## تعریف «انجام شد»

یک نیاز وقتی «انجام‌شده» است که:
1. همه‌ی معیارهای پذیرش آن در محیط استیجینگ پاس شوند،
2. تست خودکار یا اسکریپت قابل اجرا داشته باشد ([۱۴](14-TESTING.md))،
3. مستند مربوطه به‌روز شده باشد،
4. هیچ یافته‌ی P0/P1 باز مرتبط با آن باقی نمانده باشد.
