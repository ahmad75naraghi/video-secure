<a id="f-01"></a>
## F-01 — پلی‌لیست و سگمنت‌ها بدون هیچ احراز هویتی از `uploads` سرو می‌شوند

| | |
|---|---|
| **سطح** | P0 — بحرانی |
| **CWE** | [CWE-284](https://cwe.mitre.org/data/definitions/284.html) کنترل دسترسی نامناسب، [CWE-552](https://cwe.mitre.org/data/definitions/552.html) دسترسی به فایل‌های خارج از مرز |
| **محل** | `L49-L50` (تعریف مسیر)، `L309` (ساخت URL)، `L160-L193` (محل نوشتن فایل) |

### توضیح
فایل‌های HLS در `wp-content/uploads/secure_videos/{name}/` نوشته می‌شوند و URL آن‌ها مستقیماً در پلیر قرار می‌گیرد:

```php
// L49
public static function get_videos_dir(): string { return wp_upload_dir()['basedir'] . '/secure_videos/'; }
// L309
$m3u8_url = self::get_videos_url() . $video_name . '/' . $video_name . '.m3u8';
```

`uploads` به‌صورت پیش‌فرض توسط وب‌سرور سرو می‌شود و هیچ قاعده‌ای در `.htaccess`/`nginx.conf` برای بستن `secure_videos` وجود ندارد (پلاگین هیچ فایل محافظتی نمی‌سازد). رمزنگاری AES-128 هم بی‌فایده است، چون **کلید رمزنگاری در F-02 قابل دریافت است** و در بدترین حالت چون کلید و فایل هر دو در دسترس‌اند، کاملاً قابل رمزگشایی است.

### بازتولید
```bash
# بدون کوکی، بدون لاگین
curl -s -o /tmp/p.m3u8 "https://example.com/wp-content/uploads/secure_videos/lesson-108/lesson-108.m3u8"
head -3 /tmp/p.m3u8
# #EXTM3U
# #EXT-X-VERSION:3
# #EXT-X-KEY:METHOD=AES-128,URI="https://example.com/wp-admin/admin-ajax.php?action=secure_hls_key&video=lesson-108"
curl -s "https://example.com/wp-content/uploads/secure_videos/lesson-108/000.ts" -o /tmp/0.ts
ls -l /tmp/0.ts     # فایل وجود دارد و بایت گرفته می‌شود
```
با `wget -r` یا `ffmpeg -i <m3u8> -c copy out.mp4` و داشتن کوکی یک حساب رایگان، کل ویدیو قابل استخراج است.

### اثر
نیاز شماره ۱ شما («قابل دانلود نباشد») **کاملاً برآورده نمی‌شود**. همچنین نیاز ۲ و ۳ بی‌معنا می‌شوند، چون مهاجم اصلاً پلیر و واترمارک را دور می‌زند.

### راه‌حل
1. **خروج فایل‌ها از web root** (اصلاح ریشه‌ای):
```php
// پیشنهادی: قابل تنظیم با ثابت، پیش‌فرض خارج از ABSPATH
public static function storage_root(): string {
    if ( defined( 'FALNIC_STORAGE_DIR' ) ) {
        return trailingslashit( FALNIC_STORAGE_DIR );
    }
    return trailingslashit( dirname( ABSPATH ) . '/falnic-secure' );
}
```
2. **سرو از طریق یک کنترلر با احراز هویت** ([۰۹-تحویل استریم](09-STREAM-DELIVERY.md)) — دیگر هیچ URL مستقیمی در HTML چاپ نمی‌شود.
3. **جلوگیری از دسترسی مستقیم حتی هنگام خطا**: اگر چاره‌ای جز نگه‌داشتن فایل‌ها در `uploads` ندارید، پوشه را با `.htaccess` و `web.config` ببندید و نام‌ها را تصادفی کنید (تا وقتی سرور مهاجرت نکرده، این یک باند‌اید موقت است، نه راه‌حل).
4. **مهاجرت**: پوشه‌ی فعلی حذف و لینک‌های قبلی ۴۰۳ شوند؛ جزئیات در [۱۶-مهاجرت](16-MIGRATION.md).

### تست پذیرش
```bash
# باید 403/404 بدهد
curl -s -o /dev/null -w '%{http_code}\n' "https://example.com/wp-content/uploads/secure_videos/lesson-108/000.ts"
# باید 403/404 بدهد
curl -s -o /dev/null -w '%{http_code}\n' "https://example.com/wp-content/falnic-secure/videos/v_9f2c/720p/00001.ts"
```

<a id="f-02"></a>
## F-02 — دریافت کلید AES برای هر ویدیو توسط هر کاربر لاگین‌کرده (IDOR)

| | |
|---|---|
| **سطح** | P0 — بحرانی |
| **CWE** | [CWE-639](https://cwe.mitre.org/data/definitions/639.html) دسترسی به شیء با شناسه‌ی کاربر دیگر، [CWE-862](https://cwe.mitre.org/data/definitions/862.html) نبود بررسی مجوز |
| **محل** | `L23` (ثبت هوک)، `L280-L302` |

### توضیح
```php
public function deliver_key() {
    if ( ! is_user_logged_in() ) wp_die( 'Unauthorized', '', [ 'response' => 401 ] );
    // ...
    $video_name = sanitize_text_field( $_GET['video'] ?? '' );
    $key_path = self::get_secure_dir() . $video_name . '/' . $video_name . '.key';
    echo file_get_contents( $key_path );
}
```
تنها شرط، **لاگین بودن** است. هیچ‌کدام از این‌ها بررسی نمی‌شود:
- آیا کاربر در دوره‌ی مربوط به این ویدیو ثبت‌نام کرده؟
- آیا کاربر اصلاً اجازه‌ی دیدن ویدیو را دارد؟
- آیا این ویدیو برای این کاربر/نشست صادر شده؟
- آیا تعداد درخواست‌ها محدود است؟

با یک حساب رایگان (`subscriber`) می‌توان کلید **همه‌ی ویدیوها** را گرفت.

### بازتولید
```bash
# با کوکی یک کاربر رایگان
curl -b free_user_cookies.txt \
  "https://example.com/wp-admin/admin-ajax.php?action=secure_hls_key&video=lesson-108" \
  -o key.bin
xxd key.bin     # ۱۶ بایت کلید
# سپس با کلید + IV از روی m3u8 و سگمنت‌های عمومی:
openssl aes-128-cbc -d -K "$(xxd -p key.bin)" -iv "$(grep -o 'IV=0x[0-9a-f]*' p.m3u8 | cut -c6-)" \
  -in 000.ts -out 000.ts.dec -nopad
```

### اثر
همان F-01. حتی اگر فایل‌ها را از web root خارج کنید، **تا وقتی این اندپوینت هر کلیدی را به هر کاربری می‌دهد**، محافظت شکسته است.

### راه‌حل
- بررسی دسترسی از طریق یک کلاس واحد `Access::can_watch( $user_id, $video_key )` که LearnDash، نقش و گروه را می‌بیند ([۰۷-LearnDash](07-LEARNDASH.md)).
- کلید فقط با **توکن کوتاه‌عمر** و **محدود به همان نشست** تحویل شود.
- محدودیت نرخ (مثلاً ۱۰ کلید در دقیقه برای هر کاربر/IP) و لاگ هر درخواست.
- پاسخ بدون کش، با `Content-Length` و `X-Content-Type-Options: nosniff`.

```php
public function deliver_key( WP_REST_Request $req ) {
    $video_key = sanitize_key( $req['v'] );
    if ( ! Token::verify( $req['t'], [ 'scope' => 'key', 'video' => $video_key ] ) ) {
        return new WP_Error( 'falnic_bad_token', 'توکن نامعتبر', [ 'status' => 403 ] );
    }
    if ( ! Access::can_watch( get_current_user_id(), $video_key ) ) {
        Logger::denied( 'key', $video_key );
        return new WP_Error( 'falnic_forbidden', 'دسترسی ندارید', [ 'status' => 403 ] );
    }
    // ... ارسال کلید
}
```

## F-03 — کلید در manifest لو می‌رود و لینک کلید دائمی و قابل بازپخش است

| | |
|---|---|
| **سطح** | P0 — بحرانی |
| **CWE** | [CWE-200](https://cwe.mitre.org/data/definitions/200.html) افشای اطلاعات، [CWE-798](https://cwe.mitre.org/data/definitions/798.html) اعتبارنامه‌ی ثابت |
| **محل** | `L174-L178` |

### توضیح
```php
$key_url = admin_url( "admin-ajax.php?action=secure_hls_key&video=$name" );
file_put_contents( $keyinfo_file, "$key_url\n$key_file\n$iv" );
```
ffmpeg این URL را عیناً در `#EXT-X-KEY` می‌نویسد. نتیجه:

1. **هر کسی که m3u8 را ببیند، آدرس کلید را می‌بیند** — کلید نه مخفی است، نه توکنی دارد، نه انقضایی.
2. **لینک قابل بازپخش است**: با یک بار لاگین، همان URL را می‌توان در `curl`، `yt-dlp`، `ffmpeg` یا هر ابزار بیرونی استفاده کرد. پلیر هیچ نقشی در اعتبارسنجی ندارد.
3. **IV در همان فایل نوشته می‌شود** و از manifest قابل خواندن است؛ IV مخفی نیست (طبیعی است) اما کلید هم عملاً همان‌قدر عمومی می‌شود.
4. لینک کلید به دامنه‌ی سایت وابسته است؛ اگر سایت مهاجرت کند، همه‌ی m3u8های قدیمی می‌شکنند.

### راه‌حل
- در زمان انکود، URI کلید را **نسبی و بی‌معنی** بنویسید، مثلاً `URI="k"` با `-hls_key_info_file` و سپس **بازنویسی manifest در زمان درخواست** با یک URI امضاشده‌ی مخصوص همان نشست ([۰۹](09-STREAM-DELIVERY.md)).
- کلید هرگز نباید با یک URL ثابت قابل واکشی باشد.

## F-04 — هیچ بررسی دسترسی دوره/درس وجود ندارد؛ embed فقط «لاگین بودن» را چک می‌کند

| | |
|---|---|
| **سطح** | P0 — بحرانی |
| **CWE** | [CWE-862](https://cwe.mitre.org/data/definitions/862.html)، [CWE-285](https://cwe.mitre.org/data/definitions/285.html) |
| **محل** | `L261-L270`، نبود هرگونه کد LearnDash در کل فایل |

### توضیح
```php
public function render_embed_endpoint() {
    if ( isset( $_GET['falnic_embed'] ) ) {
        $video_name = sanitize_text_field( $_GET['falnic_embed'] );
        if ( ! is_user_logged_in() ) { wp_die( 'شما دسترسی ندارید.', ... ); }
        echo ... $this->render_player( ['name' => $video_name] ) ...;
```
- هیچ اشاره‌ای به `sfwd_lms_has_access`، `learndash_get_course_id`، ثبت‌نام در دوره، گروه یا نقش وجود ندارد.
- عنوان ویدیو آزادانه از query string خوانده می‌شود؛ یعنی **هر کاربر لاگین‌کرده می‌تواند هر ویدیویی را با حدس زدن نام پخش کند** (نام‌ها قابل حدس‌اند — F-07).
- ستون «لینک Embed» در لیست مدیریت (L76-L79) همین URL را به ادمین می‌دهد و این تصور غلط را می‌سازد که امنیت دارد.

### اثر
نیاز شماره ۴ شما («قرار گرفتن در درس و محدود شدن به دانشجوی همان دوره») **پیاده‌سازی نشده**؛ حتی اگر ویدیوها را در درس بگذارید، کاربر رایگان با یک URL به آن‌ها می‌رسد.

### راه‌حل
یک نقطه‌ی تصمیم واحد (جزئیات کامل در [۰۷](07-LEARNDASH.md)):
```php
final class Access {
    public static function can_watch( int $user_id, string $video_key ): bool {
        if ( user_can( $user_id, 'manage_options' ) ) return true;
        $video = Video::find( $video_key );
        if ( ! $video ) return false;

        foreach ( $video->lesson_ids as $lesson_id ) {
            $course_id = (int) learndash_get_course_id( $lesson_id );
            if ( $course_id && function_exists( 'sfwd_lms_has_access' )
                 && sfwd_lms_has_access( $course_id, $user_id ) ) {
                return true;
            }
        }
        return (bool) apply_filters( 'falnic_can_watch', false, $user_id, $video );
    }
}
```
و این تابع باید در **همه‌ی** مسیرها صدا زده شود: رندر پلیر، manifest، سگمنت، کلید.

## F-05 — دستکاری مسیر (Path Manipulation) در پارامتر `video` و `falnic_embed`

| | |
|---|---|
| **سطح** | P1 — بالا (در صورت وجود فایل با الگوی مشابه، به P0 نزدیک می‌شود) |
| **CWE** | [CWE-22](https://cwe.mitre.org/data/definitions/22.html) Path Traversal |
| **محل** | `L292-L296`، `L306-L309`، `L263` |

### توضیح
`sanitize_text_field()` کاراکترهای `/` و `.` را حذف نمی‌کند:
```php
$video_name = sanitize_text_field( $_GET['video'] ?? '' );   // ورودی آزاد
$key_path   = self::get_secure_dir() . $video_name . '/' . $video_name . '.key';
```
ورودی‌هایی مثل `../foo` باعث می‌شوند مسیر از پوشه‌ی مورد انتظار خارج شود. الگوی تکرارشده‌ی `{x}/{x}.key` امکان خواندن هر فایلی را نمی‌دهد، اما **امکان خروج از پوشه و دسترسی به کلید ویدیوهای دیگر** را می‌دهد؛ یعنی حتی اگر F-02 را با چک دسترسی ببندید، یک مهاجم می‌تواند با مسیر دستکاری‌شده بررسی را دور بزند (چون بررسی روی `$video_name` انجام می‌شود و خواندن روی مسیر نرمال‌شده).
همین موضوع برای `render_player` و `?falnic_embed=` هم هست؛ در embed نام به `render_player` می‌رود و در آنجا مسیر m3u8 ساخته می‌شود.

### راه‌حل
- هرگز نام پست/عنوان را به مسیر تبدیل نکنید. از `video_key` استفاده کنید.
- اعتبارسنجی سخت‌گیرانه:
```php
$video_key = (string) $req['v'];
if ( ! preg_match( '/^v_[a-f0-9]{16}$/', $video_key ) ) {
    return new WP_Error( 'falnic_bad_id', '', [ 'status' => 400 ] );
}
$path = realpath( Storage::videos_dir() . $video_key );
if ( $path === false || strpos( $path, realpath( Storage::videos_dir() ) ) !== 0 ) {
    return new WP_Error( 'falnic_bad_path', '', [ 'status' => 400 ] );
}
```
- برای نام فایل سگمنت هم فقط عدد مجاز باشد (`^\d{5}$`).

<a id="f-06"></a>
## F-06 — کلید ثابت برای همه‌ی سگمنت‌ها، بدون چرخش، با مجوز فایل نامشخص

| | |
|---|---|
| **سطح** | P1 — بالا |
| **CWE** | [CWE-320](https://cwe.mitre.org/data/definitions/320.html) خطای مدیریت کلید، [CWE-732](https://cwe.mitre.org/data/definitions/732.html) مجوز نادرست فایل |
| **محل** | `L171-L178` |

### توضیح
```php
$iv = bin2hex( random_bytes( 16 ) );
file_put_contents( $key_file, random_bytes( 16 ) );
```
- **یک کلید برای کل ویدیو**؛ اگر یک بار لو برود، کل ویدیو (گذشته و آینده، تا انکود بعدی) رمزگشایی می‌شود.
- `file_put_contents` بدون `chmod`؛ با umask معمول (`022`) فایل `0644` می‌شود، یعنی **همه‌ی کاربران سیستم** می‌توانند بخوانند. روی هاست اشتراکی این یک ریسک واقعی است.
- کلید هرگز چرخش نمی‌کند؛ توصیه‌ی HLS استفاده از `#EXT-X-KEY` متعدد است.

### راه‌حل
```bash
# چرخش کلید هر ۴۰ سگمنت (≈۶.۶ دقیقه با hls_time=10)
ffmpeg ... -hls_time 10 -hls_flags periodic_rekey \
  -hls_key_info_file "${keyinfo}" ...
```
و در PHP:
```php
file_put_contents( $key_file, random_bytes( 16 ), LOCK_EX );
chmod( $key_file, 0600 );
chmod( dirname( $key_file ), 0700 );
```
هر `key_id` جداگانه و فقط برای بازه‌ی زمانی مربوط به خودش مجاز شود ([۰۹](09-STREAM-DELIVERY.md#چرخش-کلید)).

## F-07 — شناسه‌ی ویدیوها قابل حدس و قابل شمارش است

| | |
|---|---|

## F-08 — فایل `keyinfo` (شامل مسیر مطلق کلید) در صورت خطا/تایم‌اوت روی دیسک می‌ماند

| | |
|---|---|
| **سطح** | P1 — بالا |
| **CWE** | [CWE-212](https://cwe.mitre.org/data/definitions/212.html) ذخیره‌ی ناخواسته‌ی اطلاعات حساس |
| **محل** | `L176-L186` |

### توضیح
```php
file_put_contents( $keyinfo_file, "$key_url\n$key_file\n$iv" );
exec( $ffmpeg_cmd, $output, $return_var );
unlink( $keyinfo_file );       // فقط اگر exec برگردد
```
اگر ffmpeg هنگ کند، تایم‌اوت شود، پراکسی درخواست را قطع کند یا PHP کشته شود، فایل `keyinfo` با مسیر مطلق کلید و URL کلید باقی می‌ماند. اگر پوشه اشتباهاً سرو شود، این فایل نقشه‌ی راه است.

```php
try {

```
و `keyinfo` را در `tmp/` با `0600` بسازید، نه کنار کلید.

## F-09 — CSRF در ذخیره‌ی تنظیمات

- **محل:** `L200-L204`

- **توضیح:** `if ( isset( $_POST['falnic_save_settings'] ) )` بدون `check_admin_referer`/nonce. یک صفحه‌ی مخرب می‌تواند `max_sessions` را تغییر دهد یا `bind_ip` را خاموش کند. (بررسی `current_user_can` به‌صورت غیرمستقیم از طریق capability منو انجام می‌شود، ولی CSRF را نمی‌بندد.)

```php
check_admin_referer( 'falnic_settings' );
if ( ! current_user_can( 'manage_options' ) ) wp_die( '', 403 );
```

## F-12 — کنترل نشست ناکارآمد و مبنای IP اشتباه

- **محل:** `L272-L278`، `L283-L290`
- **CWE-613 / CWE-290**
- **توضیح:**
  - فقط حالت `max_sessions === 1` کاری می‌کند و آن هم با `wp_destroy_other_sessions()`؛ بقیه‌ی مقادیر هیچ اثری ندارند.
  - `falnic_last_login_ip` فقط در لحظه‌ی لاگین ست می‌شود؛ اگر IP کاربر عوض شود، دیگر هرگز به‌روز نمی‌شود.

<a id="f-13"></a>
## F-13 — اعتبارسنجی آپلود تقریباً وجود ندارد

- **محل:** `L132-L134`
- **CWE-434 / CWE-400**
- **توضیح:** فقط `UPLOAD_ERR_OK` چک می‌شود. نه حجم، نه MIME واقعی، نه پسوند، نه `is_uploaded_file`. خطاهای آپلود (`UPLOAD_ERR_INI_SIZE` و…) بی‌صدا نادیده گرفته می‌شوند و ادمین فکر می‌کند ویدیو آپلود شده. فایل دلخواه به ffmpeg داده می‌شود (پارس‌کننده‌ی C با تاریخچه‌ی باگ).
- **راه‌حل:**
```php
if ( ! isset( $_FILES['falnic_video_file'] ) ) return;
$f = $_FILES['falnic_video_file'];
if ( $f['error'] !== UPLOAD_ERR_OK ) { /* پیام دقیق بر اساس کد خطا */ return; }
if ( ! is_uploaded_file( $f['tmp_name'] ) ) return;
if ( $f['size'] > (int) get_option( 'falnic_max_upload_mb', 4096 ) * MB_IN_BYTES ) { /* خطا */ return; }
$mime = wp_check_filetype_and_ext( $f['tmp_name'], $f['name'] );
if ( ! in_array( $mime['ext'], [ 'mp4', 'm4v', 'mov' ], true ) ) { /* خطا */ return; }
```

## F-14 — `glob()` + `array_map` می‌تواند خطای مرگبار بدهد و پاکسازی ناقص است

- **محل:** `L138-L139`
- **CWE-703**

<a id="f-15"></a>
## F-15 — انکود همگام در `save_post` (تایم‌اوت، تکرار، قفل نبودن)

- **محل:** `L132-L145`، `L160-L193`
- **CWE-400 / CWE-362**
- **توضیح:** انکود یک ویدیوی ۱ ساعته ساعت‌ها طول می‌کشد. درخواست ذخیره تا آخر باز می‌ماند؛ تایم‌اوت وب‌سرور/پروکسی باعث «ذخیره‌ی ناموفق» و تلاش دوباره می‌شود، در حالی که ffmpeg هنوز روی همان پوشه کار می‌کند. دو ذخیره‌ی هم‌زمان = سگمنت‌های خراب. هیچ صفی، وضعیتی، قفلی یا بازگردانی‌ای وجود ندارد.
- **راه‌حل:** صف (Action Scheduler یا جدول اختصاصی) + قفل فایل (`flock`) + وضعیت `queued|processing|ready|failed` در متا + صفحه‌ی پیشرفت.

<a id="f-16"></a>
## F-16 — `eval` + ضد‌دیباگ که صفحه را پاک می‌کند

- **محل:** `L320-L330`، `L347`
- **CWE-95 / CWE-693**
- **توضیح:**
```js
setInterval(function(){
  const s = new Date().getTime(); debugger;
  if ( new Date().getTime() - s > 100 ) {
      document.body.innerHTML = '<h1 ...>Access Denied</h1>';
      window.location.replace('about:blank');
  }
}, 1000);
```
  - روی گوشی ضعیف، تب کند، با DevTools باز یا حتی هنگام جمع‌شدن `debugger` توسط افزونه‌ها، **کاربر واقعی صفحه‌ی سفید می‌بیند**. این باگ تجربه‌ی کاربری است، نه امنیت.
  - `eval(atob(...))` نیازمند `unsafe-eval` در CSP است؛ یعنی کل سایت باید CSP ضعیف داشته باشد.
  - هر مهاجمی با غیرفعال کردن JS یا حذف این بلاک، دور می‌زند. **مانع ضبط صفحه نمی‌شود.**
  - `document.body.innerHTML = ...` با کلیدواژه‌های فارسی/انگلیسی داخل رشته، احتمال خرابی نقل‌قول دارد.
- **راه‌حل:** حذف کامل. جایگزین: واترمارک + لاگ + محدودیت هم‌زمانی ([۰۸](08-WATERMARKING.md)).

<a id="f-17"></a>
## F-17 — اسکریپت‌های CDN بدون نسخه‌ی پین‌شده و بدون SRI

- **محل:** `L334`، `L344`، `L345`
- **CWE-1104 / CWE-353**
- **توضیح:** `hls.js@latest` هر لحظه می‌تواند تغییر کند؛ یک انتشار ناسازگار کل پلیر را می‌شکند. هیچ‌کدام `integrity` ندارند. اگر `cdn.jsdelivr.net` یا `cdn.plyr.io` در شبکه‌ی کاربر فیلتر باشد، پلیر فقط صفحه‌ی سیاه نشان می‌دهد و هیچ پیام خطایی هم نمی‌دهد.
- **راه‌حل:** باندل کردن نسخه‌ی مشخص در `assets/js/vendor/`، بارگذاری با `wp_enqueue_script`، و در صورت استفاده از CDN حتماً `integrity` + `crossorigin`.

<a id="f-18"></a>
## F-18 — اندپوینت کلید: بدون محدودیت نرخ، بدون لاگ، بدون هدرهای امنیتی

- **محل:** `L298-L300`
- **CWE-770 / CWE-778**
- **توضیح:** `Cache-Control: no-store` درست است، اما:
  - محدودیت نرخ ندارد → شمارش نام ویدیوها و گرفتن همه‌ی کلیدها در چند دقیقه.
  - هیچ لاگی ثبت نمی‌شود → بعد از نشتی نمی‌توانید بگویید چه کسی کلید را گرفته.
  - `X-Content-Type-Options: nosniff` و `Content-Length` ندارد.
  - خطاها با `wp_die` و خروجی HTML برمی‌گردند؛ پلیر نمی‌تواند خطا را تشخیص دهد و صفحه سیاه می‌شود.
- **راه‌حل:** REST + JSON، rate limit بر اساس کاربر و IP، لاگ اجباری، وضعیت‌های خطای مشخص.

## F-19 — تزریق نام/ایمیل کاربر داخل رشته‌ی JS با `esc_js`

- **محل:** `L352-L353`
- **CWE-79**
- **توضیح:** `esc_js()` برای رشته‌های داخل نقل‌قول تک درست است اما `</script>` را خنثی نمی‌کند. اگر نام یا ایمیل کاربر شامل `</script><script>…` باشد، بلاک اسکریپت بسته می‌شود. (اکثر فیلدهای پروفایل توسط وردپرس پاک‌سازی می‌شوند، اما تکیه بر این رفتار در برابر یک فیلد متای قابل ویرایش کافی نیست.)

<a id="f-20"></a>
## F-20 — واترمارک canvas در توقف/جست‌وجو/فول‌اسکرین موبایل ناپدید می‌شود

- **محل:** `L370-L388`
- **CWE-693**
- **توضیح:**
  - `rFrame()` وقتی `video.paused` است برمی‌گردد؛ پس در توقف، آخرین فریم با واترمارک باقی می‌ماند اما پس از `seek` فریم جدید بدون واترمارک رسم نمی‌شود.
  - در iOS، ویدیوی `playsinline` وارد فول‌اسکرین بومی می‌شود و **canvas زیر آن دیده نمی‌شود** → واترمارک از بین می‌رود.
  - `canvas.width = video.videoWidth` یعنی رسم با رزولوشن کامل واتدیو در هر فریم → مصرف CPU/باتری بالا و افت فریم.
  - هیچ شناسه‌ی نشست/زمان در واترمارک نیست؛ بنابراین حتی اگر ویدیو ضبط شود، ردیابی دقیق سخت است.
- **راه‌حل:** بازنویسی خط لوله ([۱۰-PLAYER](10-PLAYER.md)): رسم مستقل از `paused`، رسم مجدد روی `seeked`/`visibilitychange`، رسم در رزولوشن نمایش، ممنوع کردن فول‌اسکرین بومی در موبایل (به‌جای آن fullscreen API روی کانتینر)، و افزودن `user_id + session_id + timestamp` به واترمارک.

<a id="f-21"></a>
## F-21 — واترمارک فقط سمت کلاینت است

- **محل:** `L332-L414`
- **CWE-693**
- **توضیح:** واترمارک در مرورگر کشیده می‌شود. با دانلود سگمنت‌ها (F-01) یا گرفتن استریم، ویدیوی بدون واترمارک به دست می‌آید. برای اثر واقعی باید واترمارک **در تصویر** باشد (سرورساید) یا حداقل جایی باشد که حذفش هزینه داشته باشد.
- **راه‌حل:** سه لایه در [۰۸-واترمارک](08-WATERMARKING.md): DOM/Canvas (ارزان، بازدارنده)، سوختن سرورساید برای دوره‌های حساس، و واترمارک A/B فورنزیک برای شناسایی منبع نشتی.

<a id="f-22"></a>
## F-22 — هیچ لاگ یا ردیابی‌ای وجود ندارد

- **محل:** کل فایل
- **توضیح:** نه لاگ دسترسی، نه لاگ پخش، نه لاگ رد شدن. اگر ویدیو در تلگرام پخش شود، هیچ راهی برای فهمیدن منبع ندارید.
- **راه‌حل:** جدول `falnic_access_log` (کاربر، ویدیو، نوع درخواست، IP، UA، نتیجه، زمان) + پاکسازی دوره‌ای + گزارش در مدیریت.

<a id="f-23"></a>
## F-23 — محدودیت پخش هم‌زمان واقعاً اعمال نمی‌شود

- **محل:** `L272-L278`
- **توضیح:** تنها اقدام، بستن نشست‌های قبلی در لحظه‌ی لاگین است. کاربر می‌تواند در دو مرورگر با یک کوکی پخش کند؛ اشتراک‌گذاری اکانت تشخیص داده نمی‌شود.

<a id="f-25"></a>
## F-25 — هک `str_replace('http://','https://')` روی `admin_url`

- **محل:** `L175-L176`
- **توضیح:** اگر سایت روی HTTPS باشد ولی `admin_url` از `http` بیاید (reverse proxy نادرست)، این جایگزینی رشته‌ای ممکن است دامنه را در مسیر هم عوض کند؛ در محیط لوکال/استیجینگ که HTTPS نیست، کلید با `https` درخواست می‌شود و شکست می‌خورد.

## F-26 — اجبار HTTPS در URL ویدیو

- **محل:** `L50`
- **توضیح:** `set_url_scheme( ..., 'https' )` روی محیط توسعه/استیجینگ بدون گواهی، پلیر را می‌شکند (mixed content یا خطای اتصال).
- **راه‌حل:** هم‌سو با `home_url()` و `is_ssl()`؛ یا کاملاً از مسیر کنترلر (بدون URL ایستا) استفاده کنید.

<a id="f-27"></a>
## F-27 — embed بدون `frame-ancestors`، بدون `no-cache`، بدون بررسی Referer

- **محل:** `L261-L269`
- **توضیح:** صفحه‌ی embed در قالب HTML خالی چاپ می‌شود:
  - `X-Frame-Options`/CSP تنظیم نمی‌شود → هر سایتی می‌تواند آن را iframe کند و روی آن کلیک‌ربایی کند.
  - کش نمی‌شود خنثی کرد؛ ممکن است نسخه‌ی کش‌شده به کاربر دیگری نشان داده شود.
  - بدون `Referrer-Policy`، URL کامل به سایت‌های بیرونی در لینک‌ها لو می‌رود.
- **راه‌حل:**
```php
nocache_headers();
header( "Content-Security-Policy: frame-ancestors 'self' https://learn.example.com" );
header( 'Referrer-Policy: no-referrer' );
header( 'X-Content-Type-Options: nosniff' );
```

`L1-L8`: بدون `Text Domain`، `Domain Path`، `License`، `Requires at least`، `Requires PHP` (به‌شکل استاندارد). بدون این‌ها ترجمه و به‌روزرسانی خودکار درست کار نمی‌کند.

<a id="f-30"></a>
## F-30 — بدون i18n
همه‌ی رشته‌ها مستقیم در کد فارسی هستند (مثلاً `L58`، `L94`، `L257`). استفاده از `__()` با text domain `falnic-secure-hls` لازم است تا پروژه قابل نگهداری و ترجمه باشد.

<a id="f-31"></a>
## F-31 — دستور ffmpeg ضعیف است
`L180-L184`:
- فقط یک کیفیت (بدون ABR/rendition چندگانه) → موبایل و اینترنت ضعیف تجربه‌ی بدی دارند.
- `-hls_segment_filename %03d.ts` → بعد از ۹۹۹ سگمنت (≈۲.۷ ساعت با `hls_time=10`) نام‌گذاری می‌شکند.
- `-g`/`-keyint_min`/`-sc_threshold` تنظیم نشده → مرز سگمنت‌ها ممکن است با کی‌فریم هم‌تراز نباشد و seek کند شود.
- `-movflags`/`-map` ندارد؛ ویدیوی بدون صدا یا با چند صدا مدیریت نمی‌شود.
- `-preset fast` بدون تنظیم ترد → روی هاست اشتراکی همه‌ی CPU را می‌خورد.

<a id="f-32"></a>
## F-32 — مسیر ffmpeg قابل تنظیم نیست و بررسی سلامت وجود ندارد
`L185`: فقط `ffmpeg` در PATH. اگر نبود، خطای مبهم. یک صفحه‌ی «سلامت سیستم» با بررسی `ffmpeg -version`، مجوز پوشه‌ها و نسخه‌ی PHP لازم است.

<a id="f-33"></a>
## F-33 — کلید شورت‌کد به داده‌ی قابل تغییر وابسته است
`L74`، `L304-L306`: `[secure_video name="..."]` بر پایه‌ی عنوان. تغییر عنوان = شکستن همه‌ی محتوا. باید `[secure_video id="123"]` یا `key="v_..."` باشد و `name` فقط برای سازگاری عقب‌رو نگه داشته شود.

<a id="f-34"></a>
## F-34 — دارایی‌های درون‌خطی، بدون enqueue، بدون دسترس‌پذیری
`L334-L345`: `<link>` و `<script>` مستقیم در محتوای صفحه چاپ می‌شوند (چند بار در صفحه = چند بار تگ)، بدون `wp_enqueue_script`، بدون نسخه‌بندی، و canvas تنها راه دیدن ویدیو است → صفحه‌خوان تصویری نمی‌بیند و زیرنویس پشتیبانی نمی‌شود.

# 🧰 پچ حداقلی برای بستن P0 (اگر امروز باید منتشر کنید)

این پچ کامل نیست و معماری را درست نمی‌کند، اما سه شکاف اصلی را می‌بندد. ترجیحاً به‌جای آن، فاز ۱ نقشه‌ی راه را انجام دهید.

```php
// 1) مسیر ذخیره‌سازی خارج از web root
public static function get_videos_dir(): string {
    return trailingslashit( dirname( ABSPATH ) . '/secure_media' );
}

// 2) شناسه‌ی سخت‌گیرانه + بررسی واقعی مسیر
private static function safe_name( string $raw ): ?string {
    if ( ! preg_match( '/^[a-z0-9][a-z0-9\-]{1,60}$/', $raw ) ) return null;
    $base = realpath( self::get_secure_dir() );
    $dir  = realpath( self::get_secure_dir() . $raw );
    if ( ! $base || ! $dir || strpos( $dir, $base ) !== 0 ) return null;
    return $raw;
}

// 3) در deliver_key، بعد از safe_name:
if ( ! $this->user_can_watch( get_current_user_id(), $name ) ) {
    wp_die( 'Forbidden', '', [ 'response' => 403 ] );
}
```
و مهم‌تر از همه: **پوشه‌ی `uploads/secure_videos` را حذف و در `.htaccess` مسدود کنید** تا F-01 بسته شود.

# 📉 ریسک باقی‌مانده (بعد از رفع همه‌ی موارد بالا)

این‌ها را نمی‌توان با کد این پلاگین حل کرد؛ باید آگاهانه بپذیرید:

| ریسک | توضیح | کاهش ممکن |
|---|---|---|
| **ضبط صفحه** | کاربر می‌تواند با OBS/گوشی ضبط کند | واترمارک فورنزیک + لاگ → ردیابی، نه جلوگیری |
| **دسترسی به DOM** | کاربر فنی می‌تواند در نهایت فریم‌ها را بگیرد | DRM (Widevine/FairPlay) — پرهزینه |
| **اکانت مشترک** | چند نفر با یک اکانت | محدودیت هم‌زمانی + heartbeat + واترمارک نام |
| **نشتی توسط ادمین** | دسترسی مستقیم به فایل‌ها | اصل تفکیک وظایف، لاگ ادمین، رمزنگاری at-rest |
| **حمله به سرور** | اگر سرور هک شود، کلیدها هم لو می‌روند | امنیت سرور، پشتیبان‌گیری رمزنگاری‌شده |

> برای دوره‌های با ارزش بسیار بالا، تنها راه واقعی **DRM تجاری** (Widevine L1، FairPlay) است که هزینه و پیچیدگی زیادی دارد و با پلاگین وردپرسی معمولی به‌سادگی محقق نمی‌شود.
