# Falnic Secure HLS Player

پلاگین وردپرسی برای پخش امن ویدیوهای دوره‌های آموزشی (LearnDash) با رمزنگاری HLS، واترمارک کاربر و محدودسازی دانلود.

> **وضعیت پروژه:** نسخه‌ی `3.5.5`. رسانه‌ها بیرون از web root ذخیره می‌شوند و پلی‌لیست، سگمنت و کلید فقط از **دروازه‌ی PHP با توکن امضاشده** تحویل می‌شوند؛ دسترسی هر درخواست دوباره با **ثبت‌نام LearnDash** بررسی می‌شود. صفحه‌ی ویرایش ویدیو حالا بینندگان و اتصال به دوره را همان‌جا نشان می‌دهد. ساختار کلاس‌محور و **بدون هیچ وابستگی بیرونی** است (hls.js و Plyr داخل پلاگین باندل شده‌اند). جزئیات: [دروازه‌ی استریم](docs/09-STREAM-DELIVERY.md) و [LearnDash](docs/07-LEARNDASH.md).

## این پلاگین در یک نگاه

| | |
|---|---|
| نوع | پلاگین وردپرس (WordPress Plugin) |
| نسخه | `3.5.5` |
| PHP | ۷.۴ و بالاتر |
| وابستگی‌های سمت سرور | `ffmpeg` + `ffprobe` (با پشتیبانی `libx264` و `aac`)، `proc_open()` یا `exec()` فعال |
| وابستگی‌های سمت مرورگر | `hls.js 1.5.17` و `Plyr 3.7.8` — **باندل‌شده داخل پلاگین، بدون CDN** |
| یکپارچه‌سازی | LearnDash — متاباکس درس/مبحث + بررسی ثبت‌نام با `sfwd_lms_has_access` |
| زبان رابط کاربری | فارسی، با رشته‌های ترجمه‌پذیر (`__()` در همه‌ی متن‌ها؛ دامنه `falnic-secure-hls`) |
| مجوز | تعیین نشده — قبل از انتشار عمومی مشخص شود |

## چهار نیاز اصلی و وضعیت واقعی آن‌ها

این جدول صادقانه‌ترین بخش این مستند است. «ناقص» یعنی چیزی پیاده شده ولی هدف را برآورده نمی‌کند.

| # | نیاز | وضعیت | چرا |
|---|---|---|---|
| ۱ | ویدیو قابل دانلود نباشد | ✅ **محافظت‌شده** | پلی‌لیست، سگمنت و کلید هیچ‌گاه مستقیم سرو نمی‌شوند؛ هر درخواست توکن کوتاه‌عمرِ گره‌خورده به کاربر و نشست دارد و دسترسی دوباره بررسی می‌شود. دسترسی مستقیم به پوشه‌ها بسته است. ضبط صفحه همچنان قابل جلوگیری نیست. ([F-01](docs/02-SECURITY-AUDIT.md#f-01)) |
| ۲ | واترمارک نام کاربری و ایمیل | 🟡 **بهبود یافته** | واترمارک هر فریم روی canvas بازسازی می‌شود و متن آن فقط از پاسخ نشست (مخصوص همان کاربر) می‌آید، پس در کش صفحه لو نمی‌رود. همچنان سمت کلاینت است و در فول‌اسکرین بومی iOS دیده نمی‌شود. ([مستند واترمارک](docs/08-WATERMARKING.md)) |
| ۳ | جلوگیری از ضبط صفحه و سرقت | ⚠️ **محدود** | `eval` و `debugger` در ۳.۲ حذف شدند (چون فقط کاربر واقعی را آزار می‌دادند و ضبط را متوقف نمی‌کردند). بازدارنده‌های سبک باقی مانده‌اند؛ کاهش واقعی نیازمند واترمارک فورنزیک و لاگ است. ([مدل تهدید](docs/03-THREAT-MODEL.md)) |
| ۴ | قرار گرفتن در یک درس دوره | ✅ **پیاده‌سازی شد** | کادر «ویدیوی امن این درس» در ویرایشگر درس/مبحث؛ نمایش خودکار بالای محتوا؛ بررسی `sfwd_lms_has_access` برای دوره، احترام به Drip/پیش‌نیاز و گروه. ویدیوی بدون دوره فقط برای مدیران (یا با قابلیت `falnic_watch_videos`) باز می‌شود. ([مستند LearnDash](docs/07-LEARNDASH.md)) |

**نتیجه‌ی مهم:** نیاز ۱ و ۴ برآورده می‌شوند و نیاز ۲ و ۳ «بازدارنده» هستند، نه مانع مطلق. دو نکته‌ی عملیاتی:

- فایل‌های قدیمی که هنوز در `wp-content/uploads/secure_videos/` هستند باید یک‌بار از پنل («انتقال ویدیوهای قدیمی») منتقل شوند.
- اگر وب‌سرور Nginx است، `.htaccess` اجرا نمی‌شود؛ مسیر `secure_videos/` و ریشه‌ی `falnic-secure/` را در کانفیگ Nginx هم ببندید (نمونه در [مستند استریم](docs/09-STREAM-DELIVERY.md)).
- عنوان ویدیو می‌تواند فارسی باشد؛ شناسه‌ی فایل‌ها یک‌بار ساخته و در متای `falnic_video_name` نگه داشته می‌شود، بنابراین تغییر عنوان بعد از انکود چیزی را نمی‌شکند.

مسیر فازهای بعدی در [نقشه‌ی راه](docs/13-ROADMAP.md) آمده است.

## ساختار پروژه

```
falnic-secure-hls.php     ← bootstrap (هدر، ثابت، autoload)
includes/                 ← کلاس‌های منطق (Storage، Encoder، Player، Token، Access، Stream، Learn_Dash، …)
admin/                    ← منوها و نمای پنل
templates/                ← player.php و embed.php
assets/                   ← css/js + vendor/hls + vendor/plyr (بدون CDN)
languages/  tests/  docs/
```

نام‌گذاری استاندارد وردپرس: `class-storage.php` ↔ `Storage`. جزئیات، قاعده‌ی autoloader و سیاست دارایی‌ها: [docs/18-STRUCTURE.md](docs/18-STRUCTURE.md)

## نصب سریع (نسخه‌ی فعلی)

```bash
# 1) فایل را در پوشه‌ی پلاگین‌ها بگذارید
cp falnic-secure-hls.php /path/to/wp-content/plugins/falnic-secure-hls/

# 2) پیش‌نیازها را چک کنید
ffmpeg -version                 # باید خروجی بدهد
php -r 'var_dump(function_exists("exec"));'   # باید true باشد

# 3) پوشه‌ی کلیدها را بسازید (باید خارج از web root باشد)
mkdir -p /path/to/secure_keys && chmod 700 /path/to/secure_keys

# 4) پلاگین را فعال کنید و یک ویدیو آپلود کنید
wp plugin activate falnic-secure-hls
```

دستور دقیق‌تر، تنظیمات وب‌سرور و چک‌لیست سخت‌سازی: [docs/11-INSTALLATION.md](docs/11-INSTALLATION.md)

## سه جمله‌ای که باید قبل از ادامه بدانید

1. **«غیرقابل دانلود کردن» مطلق وجود ندارد.** هر چیزی که مرورگر پخش می‌کند باید رمزگشایی شود؛ هدف واقعی «سخت و پرهزینه کردن دانلود + قابل ردیابی کردن نشتی» است.
2. **ضبط صفحه را نمی‌توان مسدود کرد.** ابزارهایی مثل `eval` و `debugger` فقط به کاربران عادی آسیب می‌زنند. راه درست، **واترمارک فورنزیک + لاگ دسترسی** است تا در صورت انتشار ویدیو، بدانید چه کسی آن را بیرون داده.
3. **اولویت فوری رفع باگ نیست، اصلاح معماری است.** تا وقتی فایل‌های ویدیو از مسیر عمومی سرو می‌شوند، هیچ مقدار رمزنگاری، واترمارک یا `debugger` فایده‌ای ندارد.

## قدم بعدی (برای ادامه‌ی کار)

پیشنهاد شروع، **فاز ۱ نقشه‌ی راه — آیتم‌های 1.1 تا 1.6** است، چون ۸۰٪ ارزش امنیتی را می‌سازد و به LearnDash یا واترمارک دست نمی‌زند:

1. انتقال رسانه به `dirname(ABSPATH)/falnic-secure`
2. حذف/مسدودسازی `uploads/secure_videos`
3. تولید `video_key` تصادفی و مهاجرت شناسه‌ها
4. اعتبارسنجی سخت‌گیرانه شناسه + بررسی `realpath`
5. بررسی دسترسی در مسیر کلید
6. توکن HMAC برای manifest/segment/key

جزئیات، معیار پذیرش و تخمین زمان: [docs/13-ROADMAP.md](docs/13-ROADMAP.md) — مسیر مهاجرت: [docs/16-MIGRATION.md](docs/16-MIGRATION.md)
